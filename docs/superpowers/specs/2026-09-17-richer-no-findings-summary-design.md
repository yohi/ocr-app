# 指摘なしSummaryの情報量改善設計

## 目的

レビュー結果が0件のときも、レビューが実行されて問題が見つからなかったことをPR上で判断できるSummaryを投稿する。

## 出力仕様

- 判定: `指摘なし`
- レビュー対象の変更ファイル数と一覧
- 結果JSONに文字列で含まれる場合の所要時間
- 結果JSONに数値で含まれる場合のカバレッジ

変更ファイル一覧はGitHub Pull Request Files APIの結果を使用する。既存のインライン投稿、Summaryのupsert、本文長制限は維持する。

## データフロー

1. `run` が有効なコメントを正規化する。
2. 有効なコメントがある場合は既存どおりインラインレビューを投稿する。
3. Summary投稿時にPR変更ファイルを取得し、コメントのパス集計と変更ファイル一覧を構築する。
4. Summaryを既存のbot所有コメントへPATCHし、なければPOSTする。

無効なコメントしかない結果は、従来どおりSummaryを投稿しない。型が確認できない値は表示しない。

## テスト方針

- 0件結果で「指摘なし」、変更ファイル数、変更ファイル名、coverage、elapsedがSummaryに含まれることを確認する。
- 0件結果で変更ファイルがない場合も、0ファイルとして安定した本文になることを確認する。
- 既存の指摘あり、無効結果、upsert、長文、Markdown fenceのテストを通す。
